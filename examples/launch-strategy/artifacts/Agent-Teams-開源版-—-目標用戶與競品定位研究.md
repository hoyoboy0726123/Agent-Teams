## 1. 目標用戶輪廓（3 個 segment）

### Segment A：獨立開發者 / 小型新創技術團隊（1–10 人）
- **核心痛點**
  - 已經自費訂閱 Claude Pro/Max、ChatGPT Plus/Pro，但多 Agent 工具（CrewAI、AutoGen 等）預設走 API 計量制，等於「訂閱費 + API 費」雙重付錢。
  - 團隊小、預算敏感，對「每次多 Agent 協作跑一次就燒掉幾塊美金 token」高度反感。
  - 想要的是「跟隊友協作」的體感（看得到彼此 agent 在做什麼、共同任務板），而不是純程式框架（CrewAI/AutoGen 需要寫程式組裝，非工程背景的共同創辦人用不了）。
- **付費意願**：低（傾向用免費自架版），但願意為「省心」的 hosted 便利層 / 進階整合（如 Slack、GitHub）付小額月費（$10–30/mo/團隊等級），走 open-core 加值路線。

### Segment B：AI / Automation Agency（幫客戶做導入的接案團隊）
- **核心痛點**
  - 同時服務多個客戶，每個客戶對 AI 供應商有不同偏好/合規要求（有的要用客戶自己的 OpenAI key、有的堅持資料不能出境要 Ollama 本地跑）。單一供應商綁定的工具沒辦法滿足所有案子。
  - 需要「多租戶」「白牌」「用量歸戶到客戶」以便計費，這是純開源框架（CrewAI/AutoGen）不會內建的商業功能。
  - 需要展示給客戶看的「協作介面」（Teamily 這類 SaaS 的賣點），而不是終端機/程式碼。
- **付費意願**：中～高。這是最適合轉付費的 segment：他們有業務模式可以把成本轉嫁給終端客戶，願意為 SLA、支援、多租戶/白牌功能付費（企業版授權或 hosted 方案）。

### Segment C：企業內部 IT / RPA / 平台團隊
- **核心痛點**
  - 資安與資料治理要求必須「自架」，不能把資料丟給第三方 SaaS（這正是 Teamily 這種閉源 SaaS 打不進的門）。
  - 內部已有多個 LLM 供應商合約（Azure OpenAI、Anthropic 企業合約、內部私有化 Llama/Ollama），需要一個能「換引擎不換工作流」的平台，避免被單一供應商綁死。
  - 採購週期長、要求 SSO/RBAC/稽核紀錄、SOC2 等合規證明，且通常要看到其他企業案例才敢導入。
- **付費意願**：高，但轉換週期長（6–12 個月），且**在看到成熟案例/認證前不會輕易導入**——這是 90 天內不太可能拿下的 segment，但值得現在就開始鋪陳（企業版 waitlist、安全白皮書）。

**小結**：A 是最容易冷啟動、建立口碑與 GitHub star 的族群；B 是最快能轉現金流的族群；C 是長期高價值但週期長的族群。90 天上市策略應該「用 A 做聲量、用 B 做第一批付費客戶、用 C 做長線鋪墊」。

## 2. 競品定位分析

### 2.1 Teamily AI（閉源對標對象）⚠️ 大部分未即時驗證
由於無法連線查證，以下僅為**待確認的一般印象**，正式文件請勿引用未驗證數字：
- 定位印象：閉源 SaaS，主打「人類 + 多 AI Agent 混合團隊工作空間」的體驗（頻道、任務、多 Agent 角色分工），走的是「開箱即用、不用寫程式」的產品化路線。
- 商業模式推測：訂閱制 SaaS（按席位或按 workspace 計費），可能綁定自家 API 額度轉售給用戶（也就是用戶要嘛用官方 credit、要嘛加購）。
- **已知弱點（推測，需驗證）**：
  1. 閉源 → 企業/合規敏感客戶（Segment C）無法自架，資料需經第三方，這是硬性阻礙。
  2. 若營收模式依賴轉售 API 用量，重度使用者的邊際成本會被平台加價，形成「你自己有訂閱也沒用，還是要付費」的摩擦——這正是我們差異化訊息的最佳切入點。
  3. 缺乏 Ollama / 本地模型支援的可能性較高（SaaS 廠商較少主動支援客戶自架的本地推理，因為不利於其計費模式）。

### 2.2 相鄰開源專案定位比較

| 專案 | 定位 | 開源/商業模式 | 與我們的差異 |
|---|---|---|---|
| **CrewAI** | Python 框架，角色分工式多 Agent 編排（Role-based crews），開發者導向 | MIT 開源框架 + CrewAI Enterprise（付費 hosted 平台、可觀測性、UI） | 純程式框架起家，走「開源核心 + 企業加值」open-core 路線；但沒有強調「人類與 Agent 同框協作」的團隊工作空間體驗，更偏後端編排引擎 |
| **AutoGen（微軟）/ AG2（社群 fork）** | 研究導向的多 Agent 對話框架；2024 年治理爭議後社群 fork 出 AG2，走更開放治理 | 完全開源（MIT），微軟未大力推商業化產品（AutoGen Studio 僅低代碼實驗性 UI） | 學術/研究氣息重，生產化與團隊協作介面較弱；商業化路徑不清晰，是我們可以觀察的「開源專案缺乏商業化」的反面案例 |
| **MetaGPT** | 模擬「軟體公司」的多 Agent（PM/架構師/工程師）從一句需求生成程式碼 | 開源（MIT-like） | 場景聚焦在「自動生成軟體」，非通用的人類+多 Agent 工作空間，應用範圍較窄 |
| **Dify** | LLM 應用開發平台（workflow builder、RAG、Agent 能力），偏「build AI app」而非「team workspace」 | 開源 + Dify Cloud 付費託管 + 企業版 | 開源商業模式最接近我們（open-core + cloud + enterprise），但產品心智是「應用建構平台」，不是「多人+多Agent 團隊協作」 |
| **n8n** | 通用工作流自動化，近期加入 LangChain-based Agent 節點 | 開源（Sustainable Use License）+ n8n Cloud + 企業授權 | 使用者基礎是自動化/agency 族群（與我們 Segment B 高度重疊），但核心心智是「工作流自動化」非「團隊協作空間」，可視為潛在通路/整合夥伴而非純競品 |

**觀察**：目前市場上「開源、支援多家 LLM 訂閱/API/Ollama、且是『人類+多 Agent 共同工作空間』體驗」的產品，還沒有明顯的開源領先者——CrewAI/AutoGen 偏工程框架，Dify/n8n 偏應用/自動化建構平台。這是我們的定位空白，但也代表「教育市場」的成本會比較高（用戶還沒有這個心智模型）。

## 3. 差異化訊息素材：「自己的訂閱 + 10+ API + Ollama」

### 對各 segment 的價值判斷
- **Segment A（獨立開發者）**：價值**非常高**。這是他們最痛的點——已經在付 Claude/ChatGPT 訂閱，不想再疊加 API 帳單。這個賣點直接打中錢包，是冷啟動階段最鋒利的行銷素材。
- **Segment B（Agency）**：價值**高**，但訴求不同——重點不是省自己的錢，而是「彈性應對每個客戶的供應商合約」，賣點應強調「一套工具、多種後端」而非單純省錢。
- **Segment C（企業）**：價值**中～高**，但訴求又不同——重點是「不被單一供應商綁死、可混用內部合規的私有模型（Ollama/私有部署）」，是治理/風險管理的訴求，不是省錢訴求。

**建議**：同一個技術賣點，對三個 segment 要換三套語言（省錢 / 彈性 / 治理），這點請 @writer 在正式文件中分開撰寫訊息，不要用單一句話打三個市場。

### 成本差異估算（⚠️ 模型推算，非實測數據，需要 @analyst 協助做更精確測算或找真實 benchmark）
多 Agent 協作的 token 消耗遠高於單輪對話，因為：
- 每個 Agent 角色都要重新讀入上下文（任務描述、其他 agent 的輸出、工具結果），造成上下文重複疊加。
- 一次任務常需要多輪「提案—檢視—修正」的 agent 間往返（如本次我們團隊自己的討論流程）。

粗略估算（僅供方向參考，非精確值）：
- 一個 5-agent 協作任務、每個 agent 平均 8–10 轮、每輪 context 約 1,500–3,000 tokens → 單次任務總 token 量可能落在 **50 萬–150 萬 tokens** 量級。
- 以主流模型 API 計量價（每百萬 tokens 約數美元到十餘美元不等，依模型等級差異很大）估算，單一複雜任務可能是 **數美元到十幾美元**；若團隊每天跑數十次這類任務，月成本可能落在**數百到數千美元**。
- 相對地，Claude Pro/Max、ChatGPT Plus/Pro 是**每人每月固定 $20–約$100+ 的訂閱**（有用量護欄，但對多數個人/小團隊使用強度而言接近「隨用不另計費」的體感）。
- 若工具能讓多 Agent 協作「借用」使用者既有訂閱的額度（而非另開計量 API key），對重度使用的小團隊而言，**理論上可以把原本可能上看數百至上千美元/月的 API 帳單，壓縮到訂閱費本身（$20–$100/月/人）**——這是我們最有殺傷力的量化故事，但**目前是我方模型推算，不是實測數據**。

## Key findings
1. 三個 segment 的痛點與付費動機完全不同（省錢 / 彈性 / 治理），行銷訊息不能一套打三市場。
2. Segment B（AI/Automation Agency）最可能是 90 天內第一批付費客戶，因為他們有商業模式可轉嫁成本、且多供應商需求最強烈。
3. 相鄰開源專案（CrewAI/AutoGen/MetaGPT/Dify/n8n）目前沒有明顯佔據「開源人類+多Agent 團隊工作空間」這個定位空白，這是我們的機會，但也意味著市場教育成本高。
4. 「訂閱制 vs API 計量制」的成本差異是最鋒利的行銷武器，但目前只有理論推算，**尚無實測數據**，上市前應優先補足。
5. Teamily AI 的具體定價/弱點因網路存取限制**尚未驗證**，正式外部文件中任何具體宣稱都需要人工二次核對，以降低不實比較的公關/法律風險。
